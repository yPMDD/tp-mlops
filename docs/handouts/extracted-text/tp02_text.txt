TP 2 — Mettre en œuvre un pipeline MLOps simple
Durée : 3 h + 45 min de défis · Partie 2 du cours · Windows PowerShell




 Un pipeline transforme une suite de commandes en un enchaînement décrit, paramétré et rejouable. Vous
 construisez ici un pipeline en trois étapes piloté par un fichier de paramètres, avec une règle de validation qui refuse
 d'enregistrer un modèle insuffisant. La séance se termine par des défis notés en bonus.

  VERSION WINDOWS
  Toutes les commandes sont écrites pour Windows PowerShell. Les blocs @' ... '@ écrivent un fichier : le marqueur de
  fermeture '@ doit être en début de ligne, et le bloc se colle en entier. Les fichiers sont écrits en -Encoding ascii :
  l'encodage UTF8 de PowerShell 5.1 ajoute un marqueur invisible en tête de fichier qui empêche Python de lire
  params.yaml.




 Objectifs pédagogiques
  • Découper un traitement monolithique en étapes indépendantes et testables
  • Externaliser tous les réglages dans un fichier de paramètres
  • Structurer les exécutions MLflow en exécution parente et exécutions enfants
  • Poser une règle de validation automatique avant l'enregistrement du modèle
  • Rendre le pipeline exécutable par une seule commande, sur n'importe quel poste


 Prérequis
  • TP 1 terminé : environnement, données et serveur MLflow opérationnels
  • Le serveur MLflow démarré sur le port 5000, dans un terminal laissé ouvert

 Étape 2 — Préparation
 Cette étape lit les données brutes, effectue le découpage et écrit deux fichiers. Elle ne connaît rien du modèle.
 src/preparer.py

 @'
 import yaml, os, pandas as pd
 from sklearn.model_selection import train_test_split
 p = yaml.safe_load(open('params.yaml'))['preparation']    # lit les reglages
 df = pd.read_csv('data/transactions.csv')
 tr, te = train_test_split(df, test_size=p['test_size'],   # meme decoupage qu'aux TP 1 et 3
                           random_state=p['random_state'])
 os.makedirs('data/prepare', exist_ok=True)
 tr.to_csv('data/prepare/train.csv', index=False)          # sortie 1
 te.to_csv('data/prepare/test.csv', index=False)           # sortie 2
 print('preparation :', len(tr), 'lignes train /', len(te), 'lignes test')

  CORRECTION PAR RAPPORT À LA VERSION PRÉCÉDENTE
  La première version de cette fiche utilisait stratify=df['fraude']. La stratification est une bonne pratique sur des
  classes déséquilibrées, mais elle produit un découpage différent de celui des TP 1 et 3 : le F1 tombe alors à 0,7849, sous
  le seuil de 0,82, et le modèle est refusé à l'étape 5. On la retire ici pour garder un découpage identique d'un TP à l'autre, et
  donc des résultats comparables. La question 6 du compte rendu y revient.



 Étape 3 — Entraînement
 Cette étape ne lit que les fichiers produits par l'étape 1. Elle ne refait jamais le découpage : c'est ce qui garantit que
 l'évaluation porte toujours sur les mêmes lignes.
 src/entrainer.py

 @'
 import yaml, pandas as pd, joblib
 from sklearn.ensemble import RandomForestClassifier
 p = yaml.safe_load(open('params.yaml'))['entrainement']
 tr = pd.read_csv('data/prepare/train.csv')                 # entree : sortie de l'etape 1
 X, y = tr.drop(columns='fraude'), tr['fraude']
 m = RandomForestClassifier(n_estimators=p['n_estimators'],
                            max_depth=p['max_depth'], random_state=42).fit(X, y)
 joblib.dump(m, 'models/model.pkl')                         # sortie : l'artefact modele
 print('entrainement : modele ecrit dans models/model.pkl')

 Étape 5 — Orchestrer les trois étapes avec une règle de validation
 Le pipeline enchaîne les étapes, journalise le tout dans une exécution parente MLflow, puis n'enregistre le modèle
 que si la métrique dépasse le seuil.
 pipeline.py

 @'
 import subprocess, json, yaml, joblib, mlflow, mlflow.sklearn
 P = yaml.safe_load(open('params.yaml'))
 mlflow.set_tracking_uri('http://127.0.0.1:5000')
 mlflow.set_experiment('tp2-pipeline')
 with mlflow.start_run(run_name='pipeline'):                 # execution parente
     for etape in ['preparer', 'entrainer', 'evaluer']:
         with mlflow.start_run(run_name=etape, nested=True): # execution enfant
             subprocess.run(['python', f'src/{etape}.py'], check=True)
     mets = json.load(open('reports/metrics.json'))
     mlflow.log_params({**P['preparation'], **P['entrainement']})
     mlflow.log_metrics(mets)
     mlflow.log_artifact('reports/confusion.png')
     seuil = P['validation']['seuil_f1']
     if mets['f1'] >= seuil:                                 # regle de validation
         mlflow.sklearn.log_model(joblib.load('models/model.pkl'), name='model',
                                  registered_model_name='fraude-tp2',
                                  skops_trusted_types=['sklearn.tree._tree.Tree'])
         print(f"modele accepte (F1 {mets['f1']} >= {seuil}) et enregistre")
     else:
         mlflow.set_tag('statut', 'refuse')
         raise SystemExit(f"modele refuse : F1 {mets['f1']} < seuil {seuil}")

  POURQUOI skops_trusted_types ?
  Depuis MLflow 3.16, les modèles scikit-learn sont enregistrés au format sécurisé skops, qui refuse par défaut les structures
  internes d'une forêt aléatoire. Sans cette option, l'enregistrement échoue avec « untrusted types ». On déclare ici
  explicitement faire confiance au modèle que l'on vient d'entraîner soi-même.

 Défi 1 — Le meilleur modèle… sous contraintes
 Objectif : obtenir le meilleur F1 avec un modèle qui pèse au plus 2 Mo et prédit les 1 250 lignes de test au moins trois
 fois plus vite que le modèle de base, mesuré sur votre propre machine. Vous pouvez changer d'algorithme, de
 réglages, et transformer les variables dans entrainer.py et evaluer.py.
 1. Mesurez d'abord le modèle de base :
 src/mesurer.py

 @'
 import os, json, time, statistics, joblib, pandas as pd
 m = joblib.load('models/model.pkl')
 X = pd.read_csv('data/prepare/test.csv').drop(columns='fraude')
 taille = os.path.getsize('models/model.pkl') / 1e6          # taille en Mo
 m.predict(X)                                                # premier appel : chauffe
 t = []
 for _ in range(20):                                         # 20 mesures, on garde la mediane
     d = time.perf_counter(); m.predict(X); t.append((time.perf_counter() - d) * 1000)
 latence = statistics.median(t)                              # ms pour les 1 250 lignes
 json.dump({'taille_mo': round(taille, 2), 'latence_ms': round(latence, 1)},
           open('reports/mesures.json', 'w'), indent=2)
 print(f'taille : {taille:.2f} Mo | latence : {latence:.1f} ms pour {len(X)} lignes')

 Défi 2 — Le seuil qui coûte le moins cher
 Pour la banque, une fraude manquée coûte 1 000 MAD et une fausse alerte 50 MAD. Le seuil de 0,5 n'a aucune
 raison d'être le bon. Complétez le script pour trouver le seuil qui minimise le coût total.
 src/seuil_cout.py

 @'
 import joblib, numpy as np, pandas as pd
 from sklearn.metrics import confusion_matrix
 COUT_FN, COUT_FP = 1000, 50          # fraude manquee / fausse alerte, en MAD
 te = pd.read_csv('data/prepare/test.csv')
 m = joblib.load('models/model.pkl')
 proba = m.predict_proba(te.drop(columns='fraude'))[:, 1]    # probabilite de fraude
 def cout(seuil):
     tn, fp, fn, tp = confusion_matrix(te['fraude'], (proba >= seuil).astype(int)).ravel()
     return COUT_FN * fn + COUT_FP * fp, fn, fp
 print('seuil 0.50 :', cout(0.50))
 # A COMPLETER : parcourir les seuils de 0.05 a 0.95 par pas de 0.01,
 # trouver celui qui minimise le cout, et afficher cout, fraudes manquees, fausses alertes
