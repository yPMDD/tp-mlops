TP 6 — Créer et déployer un modèle via une plateforme AutoML
Durée : 3 h · Partie 5 du cours · Windows PowerShell




Cycle complet sur une plateforme AutoML, entièrement en local et avec des outils open source : démarrer la plateforme
H2O-3 et son interface web H2O Flow, lancer une recherche AutoML reproductible, explorer le classement des modèles,
enregistrer le meilleur dans le registre MLflow, le déployer derrière un point de terminaison, l'appeler depuis un client et
mesurer sa latence. On refait ensuite la même chaîne avec FLAML, la bibliothèque légère vue au TP 5 et dans la partie
5 du cours, pour comparer ce que chaque outil coûte une fois en production. Aucun compte cloud n'est nécessaire.

     VERSION WINDOWS
     Toutes les commandes sont écrites pour Windows PowerShell (5.1 ou 7), jamais l'invite cmd.exe. Les blocs @' ... '@
     écrivent un fichier ou l'envoient à Python : le marqueur de fermeture '@ doit être en tout début de ligne, et le bloc se colle
     en entier. Les fichiers sont écrits en -Encoding ascii : l'encodage UTF8 de PowerShell 5.1 ajoute un marqueur
     invisible en tête de fichier qui casse la lecture des fichiers YAML et JSON.
     Si l'activation de l'environnement est refusée : Set-ExecutionPolicy -Scope Process -ExecutionPolicy
     RemoteSigned, puis relancez .venv\Scripts\Activate.ps1.


     CE QUI CHANGE DANS CETTE VERSION
     Le parcours Google Vertex AI est remplacé par H2O-3, la plateforme AutoML open source présentée dans la partie 5 du
     cours : tout se fait sur votre poste, sans compte ni carte bancaire. Toutes les sorties ont été obtenues réellement (H2O-3
     3.46.0.12, MLflow 3.17.2, FLAML 2.7.0). Les deux recherches AutoML ont un budget en nombre de modèles ou d'essais,
     avec une graine : relancées trois fois, elles ont donné exactement les mêmes résultats.




Objectifs pédagogiques
 •    Démarrer une plateforme AutoML locale et la piloter depuis Python et depuis son interface web
 •    Lancer une recherche AutoML reproductible et lire son classement (leaderboard)
 •    Enregistrer, versionner et promouvoir le modèle retenu dans le registre MLflow
 •    Déployer ce modèle derrière un point de terminaison et mesurer sa latence
 •    Comparer deux outils AutoML sur la qualité, la latence, la taille et les dépendances
 •    Identifier ce dont un modèle a besoin pour fonctionner en production

Étape 1 — Démarrer la plateforme H2O (15 min)
H2O-3 est un serveur Java : il garde en mémoire les données et les modèles, et expose une API et une interface web,
H2O Flow. Python ne fait que lui envoyer des ordres. On le démarre dans un terminal dédié, qui restera ouvert pendant
tout le TP.
terminal 1 : la plateforme

  cd tp-mlops; .venv\Scripts\Activate.ps1
  $JAR = (python -c "import h2o, os; print(os.path.dirname(h2o.__file__))") + "\backend\bin\h2o.jar"
  java -jar $JAR -port 54321                   # laisser ce terminal ouvert


  RÉSULTAT ATTENDU
  ... INFO water.default: Open H2O Flow in your web browser: http://...:54321

  Ouvrez http://127.0.0.1:54321 dans votre navigateur : c'est H2O Flow.



  SI H2O REFUSE DE DÉMARRER
  Message réel obtenu avec Java 21 : « Only Java versions 8-17 are supported, system version is 21.0.10 ». Installez Java
  17 et vérifiez avec java -version que c'est bien lui qui répond. En dépannage seulement, l'option
  -allow_unsupported_java force le démarrage, sans garantie. Si le port 54321 est occupé : -port 54331, et
  adaptez l'adresse dans les scripts.



Étape 2 — Lancer l'AutoML et enregistrer le meilleur modèle (25 min)
Même découpage qu'aux TP 1 à 5. Le budget est fixé en nombre de modèles et non en secondes, avec une graine, et
l'algorithme Deep Learning est exclu car il n'est pas reproductible par défaut : c'est la leçon de la partie 5 (« deux
exécutions, deux scores »). Le meilleur modèle part directement dans le registre MLflow.

terminal 2 : src/h2o_automl.py

  @'
  import h2o, pandas as pd, mlflow, mlflow.h2o
  from h2o.automl import H2OAutoML
  from sklearn.model_selection import train_test_split
  from sklearn.metrics import f1_score
  h2o.init(url='http://127.0.0.1:54321')                       # la plateforme du terminal 1
  df = pd.read_csv('data/transactions.csv')
  tr, te = train_test_split(df, test_size=0.25, random_state=42)    # decoupage des TP 1 a 5
  htr = h2o.H2OFrame(tr, destination_frame='fraude_train')
  hte = h2o.H2OFrame(te, destination_frame='fraude_test')
  for f in (htr, hte):
      f['fraude'] = f['fraude'].asfactor()                      # classification, pas regression
  aml = H2OAutoML(max_models=10, seed=42,                       # budget en modeles : reproductible
                  exclude_algos=['DeepLearning'],               # non reproductible par defaut
                  sort_metric='AUC')
  aml.train(y='fraude', training_frame=htr)
  print('projet AutoML :', aml.project_name)           # pour le retrouver dans H2O Flow
  lb = aml.leaderboard.as_data_frame()
  print(lb[['model_id', 'auc', 'logloss']].head(8).to_string(index=False))
  pred = aml.leader.predict(hte).as_data_frame()['predict'].astype(int)
  f1 = f1_score(te['fraude'], pred)
  print('modele retenu :', aml.leader.model_id, '| F1 test =', round(f1, 4))
  mlflow.set_tracking_uri('http://127.0.0.1:5000')
  mlflow.set_experiment('tp6-automl-deploiement')
  with mlflow.start_run(run_name='h2o-automl-10-modeles'):
      mlflow.log_params({'outil': 'h2o', 'max_models': 10, 'modele': aml.leader.model_id})
      mlflow.log_metric('f1', f1)
      mlflow.h2o.log_model(aml.leader, name='model', input_example=te.drop(columns='fraude').head(3),

Étape 3 — Explorer les résultats dans H2O Flow (20 min)
Partie sans code : on lit dans l'interface web ce que la recherche a produit. H2O Flow fonctionne comme un carnet : on
tape une commande dans une cellule et on l'exécute avec Ctrl+Entrée, ou on passe par les menus.
  1. Dans la première cellule de H2O Flow, tapez getLeaderboard "AutoML_1_xxx@@fraude" en remplaçant
       AutoML_1_xxx par le nom affiché par le script (ligne « projet AutoML »), puis Ctrl+Entrée. Le classement complet
       s'affiche : 12 modèles (10 modèles de base + 2 ensembles), avec leurs métriques en validation croisée, et le journal
       des décisions de l'AutoML (EVENT LOG).
  2. Faites défiler l'EVENT LOG : relevez la méthode de validation choisie (« 5-fold cross-validation ») et la graine (« Build
       control seed: 42 »).
  3. Cliquez sur le nom du modèle XGBoost_2_... (le meilleur modèle simple) : sa fiche s'ouvre. Repérez la courbe ROC,
       puis la section VARIABLE IMPORTANCES et relevez l'ordre des variables.
  4. Toujours dans la fiche, comparez la matrice de confusion TRAINING METRICS et celle de CROSS VALIDATION
       METRICS : laquelle est la plus optimiste, et pourquoi ?
  5. Menu Model > List All Models : vous retrouvez tous les modèles du serveur. Menu Model > Run AutoML... : c'est
       le même lancement que le script, entièrement à la souris (ne le lancez pas, observez seulement les réglages
       proposés).

Étape 5 — Consommer le point de terminaison et mesurer la latence (15 min)
Un client externe envoie une transaction suspecte (8 500 MAD, client récent, nuit), puis mesure 50 appels. Le port est
passé en argument : on réutilisera le même client à l'étape 6.

terminal 2 : src/client.py

  @'
  import sys, time, statistics, requests
  PORT = sys.argv[1] if len(sys.argv) > 1 else '8100'   # 8100 : H2O, 8101 : FLAML
  URL = f'http://127.0.0.1:{PORT}/invocations'
  CORPS = {'dataframe_records': [{'montant': 8500.0, 'anciennete': 3,
                                  'freq_24h': 9, 'nuit': 1}]}
  r = requests.post(URL, json=CORPS, timeout=10)
  print('reponse :', r.status_code, r.json())
  lat = []
  for _ in range(50):                            # 50 appels pour mesurer
      t = time.perf_counter()
      requests.post(URL, json=CORPS, timeout=10)
      lat.append((time.perf_counter() - t) * 1000)
  lat.sort()
  print('mediane', round(statistics.median(lat), 1), 'ms')
  print('p95    ', round(lat[int(0.95 * len(lat))], 1), 'ms')
  '@ | Set-Content -Encoding ascii src/client.py

Étape 6 — La même chaîne avec FLAML (25 min)
Deuxième AutoML, sans serveur à démarrer : FLAML est une simple bibliothèque Python. Même découpage, budget de
25 essais avec une graine. On l'enregistre, on le promeut et on le sert sur le port 8101.

terminal 2 : src/flaml_automl.py

  @'
  import pandas as pd, joblib, mlflow, mlflow.sklearn
  from flaml import AutoML
  from sklearn.model_selection import train_test_split
  from sklearn.metrics import f1_score
  df = pd.read_csv('data/transactions.csv')
  X, y = df.drop(columns='fraude'), df['fraude']
  Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=42)
  a = AutoML()
  a.fit(Xtr, ytr, task='classification', metric='f1', time_budget=-1,
        max_iter=25, seed=42, verbose=0)               # budget en essais : reproductible
  f1 = f1_score(yte, a.predict(Xte))
  print('modele retenu :', a.best_estimator, '| F1 test =', round(f1, 4))
  modele = a.model.estimator                 # le modele sous-jacent (LightGBM, XGBoost...)
  joblib.dump(modele, 'models/model_flaml.pkl')
  mlflow.set_tracking_uri('http://127.0.0.1:5000')
  mlflow.set_experiment('tp6-automl-deploiement')
  with mlflow.start_run(run_name='flaml-25-essais'):
      mlflow.log_params({'outil': 'flaml', 'max_iter': 25, 'modele': a.best_estimator})
      mlflow.log_metric('f1', f1)
      mlflow.sklearn.log_model(modele, name='model', input_example=Xte[:3],
                               serialization_format='cloudpickle',    # voir encadre
                               registered_model_name='fraude-flaml')
  '@ | Set-Content -Encoding ascii src/flaml_automl.py
  python src/flaml_automl.py

  Depuis MLflow 3.16, le format par défaut est skops, un format sécurisé qui ne sait pas enregistrer un modèle LightGBM :

Étape 7 — Panne contrôlée : de quoi dépend le service ? (10 min)
Un service en production doit survivre aux redémarrages. Testons ce qui se passe quand la plateforme H2O redémarre
alors que le point de terminaison tourne toujours.
  1. Dans le terminal 1, arrêtez H2O avec Ctrl+C, puis relancez la même commande java -jar ....
  2. Dans le terminal 2, relancez python src/client.py 8100. Le point de terminaison répond, mais par une erreur :
       notez-la.
  3. Arrêtez le terminal 3 (Ctrl+C) et relancez mlflow models serve : le modèle est rechargé dans le nouveau serveur
       H2O, le client répond de nouveau.
  4. Faites la même expérience avec FLAML : arrêtez H2O, puis appelez le port 8101. Que constatez-vous ?

     Le modèle H2O est enregistré dans un format binaire lisible seulement par la même version d'H2O. L'export autonome

     (DVC), la graine et la version exacte d'H2O et de Java.




Questions du compte rendu
